# Mafia Online — تحديث الكاميرا والتصويت التلقائي
Angular 20 standalone · Tailwind · Express · Socket.IO · MongoDB

## تشغيل النسخة الجديدة
1. فك ZIP في مجلد جديد. أوقف الخادم والواجهة القديمين.
2. احتفظ بملف server/.env الخاص بك وانسخه إلى server في النسخة الجديدة.
3. من server: npm install ثم npm run dev.
4. من client: npm ci ثم npm start.
5. حدّث صفحات جميع اللاعبين لتعمل الواجهة والخادم من الإصدار نفسه.

إن لم يكن لديك .env، انسخ server/.env.example واضبط MONGO_URI وJWT_SECRET وGOOGLE_CLIENT_ID وCLIENT_URL.
يجب تطابق GOOGLE_CLIENT_ID مع googleClientId في client/src/environments/environment.ts.
للموبايل استخدم HTTPS وعنوان API متاحًا للأجهزة، وأضف عنوان الواجهة في Google OAuth.
لا تنشر ملف .env.

## قواعد التصويت الجديدة
- انتهاء النقاش يبدأ تصويتًا مدته 45 ثانية.
- ينتهي التصويت فور تصويت جميع الأحياء، أو عند انتهاء الوقت. الغائب أو من لم يصوّت لا يُحسب له صوت.
- صاحب أعلى عدد أصوات منفردًا يأخذ 60 ثانية للدفاع. المقصود أعلى عدد، وليس اشتراط إجماع جميع اللاعبين.
- بعد الدفاع يبدأ تصويت جديد على جميع الأحياء.
- إذا تصدّر المدافع نفسه يُخرج تلقائيًا وتنكشف بطاقته للجميع.
- إذا تصدّر لاعب آخر يحصل على دقيقة دفاع، ثم تصويت جديد، وتستمر الدورة.
- دفاع قديم لا يكفي للإخراج: اللاعب يجب أن يتصدر التصويت الذي يلي دفاعه مباشرة.
- التعادل أو عدم وجود أصوات لمرشح: لا إخراج، وتبدأ ليلة جديدة.
- يمكن تغيير الصوت حتى إغلاق التصويت، ولا يمكن التصويت للنفس.
- لا يملك المضيف إنهاء التصويت أو الدفاع أو اختيار من يُخرج؛ القرار على الخادم تلقائي.
- يبقى للمضيف بدء اللعبة وضبط الأدوار وإنهاء الليل عند الحاجة وتجاوز دور الحديث.

## نتيجة الليل
إعلان ظاهر للجميع يذكر اغتيال اللاعب وبطاقته، أو «محاولة اغتيال فاشلة» عند نجاح الحماية دون كشف هوية الطبيب أو اللاعب المحمي.
إذا لم توجد محاولة أصلًا، يظهر إعلان مستقل بانتهاء الليل دون اغتيال.
إعلان الإخراج يكشف البطاقة أيضًا، وتظل البطاقة ظاهرة في قائمة اللاعبين. يبقى الإعلان حتى إخفائه محليًا أو صدور إعلان جديد، ويظهر لمن يعيد الاتصال. كل النتائج محفوظة أيضًا في سجل الجولة.

## الكاميرا والمايك
- كلا طرفي الاتصال يحجزان اتجاه الإرسال والاستقبال من البداية؛ فتح الجهاز لاحقًا لا يفقد الإرسال.
- حالة الكاميرا والمايك تُرسل عبر الخادم لكل اللاعبين، مستقلة عن وصول الفيديو.
- إشارات الاتصال تحمل رقم جلسة لمنع اختلاط ردود اتصال قديم بآخر جديد.
- إعادة محاولة تلقائية محدودة عند فشل/انقطاع الاتصال، وزر إعادة اتصال لكل لاعب.
- زر «تشغيل الصوت والفيديو» لمعالجة منع المتصفح للتشغيل التلقائي.
- المعاينة المحلية مكتومة دائمًا. المايك متاح في الردهة ثم للمتحدث/المدافع فقط بعد تفعيله.
- إذا انتهت مشاركة الجهاز من المتصفح تُحدَّث حالة الجهاز عند الجميع.
- اختبار عدة حسابات على جهاز واحد قد يتأثر باحتكار الجهاز للكاميرا أو بصوت تبويب آخر.

## واجهة الموبايل
ثلاثة عروض: الجولة، اللاعبون، بطاقتي والمزيد.
شاشة الجولة تعرض المهمة الحالية والعدّاد، وتحتها شريط لاعبين مختصر. تبويب اللاعبون يعرض كل الكاميرات، والمزيد يجمع البطاقة السرية والسجل والإدارة. عناصر الفيديو تبقى متصلة عند تغيير العرض.

## الاختبارات
- client: npm run build — نجح بناء الإنتاج، موجود في client/dist/mafia-online/browser.
- server: npm test — 12 اختبارًا تشمل دورة التصويت والدفاع، تبديل المتهم، التعادل، انتهاء الوقت، رفض الأصوات القديمة، حماية الطبيب وكشف البطاقات.
- اختُبرت 3 جلسات Chrome محلية بوسائط تجريبية: 6 اتجاهات فيديو، فتح الأجهزة بعد الاتصال، الكاميرا تشغيل/إيقاف، إعادة الاتصال، وكتم المعاينة وخارج الدور.
- اختُبرت 6 مراحل على عروض 320 و390 و1280 بكسل ببيانات تجريبية دون تجاوز أفقي أو أخطاء JavaScript.
- اختبار الوسائط استخدم جسر إشارات تجريبي؛ لم يُختبر تسجيل Google مع MongoDB حي، أو مكالمة من هواتف على شبكات مختلفة.

## حدود التشغيل
الإعداد الافتراضي يستخدم STUN فقط. الشبكات المقيدة تحتاج TURN في iceServers بملف البيئة، ويُفضّل بيانات اعتماد قصيرة الأجل من الخادم.
الاتصال Mesh قد يثقل مع عدد كبير من الكاميرات. قواعد الصوت في العملاء وليست خادم وسائط يفرض الكتم ضد عميل معدل.
حالة اللعبة في ذاكرة عملية خادم واحدة وتُفقد عند إعادة تشغيله.
